Same starting point, same benchmarks.

Qwen released two versions of its 0.5B coding model: a raw base checkpoint and an Instruct model, which Qwen’s team post-trained from that base with supervised fine-tuning and preference training. PythonGPT starts from the same base. The question was simple: with my own data, training loop and reinforcement learning, could one person on a small budget get a 0.5B model as good at Python as the official version?

Building the training set

The first checkpoint trained on about 117K rows from a single dataset and reached 28.0% on HumanEval+. More rows of the same kind were not likely to help, so for S2 I rebuilt the data around one rule: a row counts only if its code runs and its tests pass.

  • Collect. Pull each source, convert every row to one shape (instruction, code, tests), strip examples and prints from the code, and reject anything that needs files, the network, user input or non-standard packages.
  • Verify. Re-run every row’s tests in a Docker container with no network and a time limit. Rows that fail are dropped.
  • Build. Drop rows over 1,024 tokens, exact and near repeats, and anything whose function name or wording matches a HumanEval+ or MBPP+ task; cap any one function name at 30 rows; hold out 1,000 tested rows for validation.

Distilling a teacher

Asking a model to “be diverse” produces repeats, so the program decides the mix: it picks a skill from a list of about 235, a form (plain request, signature-and-docstring to complete, or buggy function to fix) and a difficulty, and DeepSeek writes ten questions per call. A second stage writes a solution plus six to ten tests for each. A third runs everything in Docker and keeps a row only if every test passes, the docstring examples written with the question still hold, and, for fix tasks, at least one test fails on the original bug.

Training

A hand-written training loop

Instead of a library trainer, S2 runs on a training loop I wrote in plain PyTorch around the Hugging Face model class. Each update takes 64 rows, sorts them by length and splits them into chunks of at most 16,000 padded positions, so long and short rows don’t waste memory on padding. Loss covers only the answer tokens and is weighted by token count across chunks, so splitting a batch never changes the gradient. I checked the loop against the library’s loss on real data and confirmed that a resumed run reproduces an uninterrupted one exactly.

Reinforcement learning on executed tests

Supervised training copies good answers. Reinforcement learning lets the model learn from its own attempts. Starting from S2, the model writes eight solutions to each problem, a sandbox runs hidden tests on each one, and a solution earns a reward of 1 only if every test passes. GRPO then makes the passing solutions more likely relative to the failing ones in the same group. Problems the model always solves or never solves teach nothing, so the task bank favors problems it gets right some of the time.

  • Task bank. — verified problems with hidden tests, filtered so S2 solves roughly 10–80% of them.
  • Sandbox. Generated code is untrusted: isolated workers with no network, no access to the tests, and limits on time, memory and output. Infrastructure failures are retried, not scored as wrong.
  • Reward. Pass or fail on correctness only, with no credit for style, length or partial tests.

What I learned

  • Closing the gap to Instruct. Which stage closed most of the gap, and what was left at the end.
  • Data quality over data volume. What changed between S1 and S2, and how much it mattered.
  • Verification is the real work. What the Docker checks caught that reading would have missed.
  • What RL added. The S2 → R2 gain and what it cost compared with more SFT.

Limits

  • The benchmark screen matches function names and wording; it can’t catch the same problem in different words, and the base model’s pretraining data can’t be audited.
  • In distillation, the teacher writes both the solution and its tests, so a shared misunderstanding can pass. Hand-reading samples is the only check on that.
  • PythonGPT is tuned for Python functions; the Instruct model is a general coding assistant. Matching it on these benchmarks doesn’t mean matching it on chat, other languages or long programs.
  • Results are from — seed(s); small differences between checkpoints, or against Instruct, may be noise.
